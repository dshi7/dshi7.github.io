## Notations

Mathematically the operator calculates `softmax(Q@K^T)@V` where online softmax is actually implemented based on a math trick.

- `D` for head dim (32\~128), `Z` for batch size (1\~8), `H` for head number (32\~128) and `N` (or N\_CTX) for sequence length (\~4K)
- The fundamental unit is `NxD` (per head, per query)
- Stacking vertically by `H`, it is `(H*N)xD` (per query)
- Keep stacking vertically by `Z`, it is `(Z*H*N)xD`, the size of `Q`, `K` and `V`

Unlike GEMM with independent output ownership along both M and N,
FA forward assign **query-row tiles** to CTAs. Each CTA:
- Input q\_tile: BMxD
- Output o\_tile: BMxD
- Internally walks over the entire K/V sequence in chunks of BN.
- BN doesn't determine CTA count.

## Nvidia Blackwell FA

Warp specialization and its memory data path

![blackwell FA memory](/assets/img/posts/fa/blackwell_FA_memory.png)

- Values in SMEM buffers `q_tile[0]` and `q_tile[1]` stay persistant through the output loop iteration entirely and are wiped only when processing the next `Q` macro-tile.
- The `qk0/qk1` are data-independent spacial splits processed simultanenously on every `BN` step.
- When `qk/acc` consumes the currnet kv tiles (a pair of `BNxD` SMEM BUF), TMA engine loads the next pair to ring buffer.

## AMD MI350x FA

Preliminaries:
- CU wavefront has VMEM pipe, LDS pipe, MFMA engine, VALU pipe and SALU pipe
- A few conflict-free LDS reads in flight => roughly fixed latency
- A few VMEM requests in flight => roughly same individual latency
- VMEM latency (300~600 cycles)
- LDS (20~40 cycles)
- MFMA (32~128 cycles)
- VALU exp2/SFU (32~80 cycles)
- VALU simple (8~32 cycles)

Baseline:
- Critical path: VMEM + LDS + QK MFMA + VEC1 + VEC2
![gfx950 FA fwd baseline diagram](/assets/img/posts/fa/gfx950_FA_fwd_baseline_diagram.png)

LDS ring (VMEM latency not fully hidden)
- Double-buffer K/V in LDS and prefetch the next tile early.
- VMEM and compute overlap, but the next K/V tile is still not ready when needed.
- Residual VMEM stall remains on the critical path.
![gfx950 FA fwd ring-LDS (VMEM latency not fully hidden)](/assets/img/posts/fa/gfx950_FA_fwd_ring_lds_vmem_not_fully_hidden.png)

LDS ring (VMEM latency fully hidden)
- Same double-buffered LDS ring, with enough lookahead.
- Next K/V tile reaches LDS before consumption.
- VMEM disappears from the critical path; LDS + QK/softmax/PV become the visible work.
![gfx950 FA fwd ring-LDS (VMEM latency fully hidden)](/assets/img/posts/fa/gfx950_FA_fwd_ring_lds_vmem_fully_hidden.png)

Warp pipeline
- Hide long VMEM latency with lookahead and LDS ring
- Overlap `PV[i]` MFMA witt `VEC1[i+1]` VALU SFU 
- Keep the MFMA pipe busy with fewer memory and softmax bubbles

```
Group A: dot1 ─ mem1 ─ dot2 ─ mem2 ─ dot1 ...
Group B:      dot1 ─ mem1 ─ dot2 ─ mem2 ─ ...
```
where
```
dot1: QK[i+1] + VEC2[i]
mem1: LDS V[i] + prefetch K[i+3]
dot2: PV[i]   + VEC1[i+1]
mem2: LDS K[i+2] + prefetch V[i+2]
```
